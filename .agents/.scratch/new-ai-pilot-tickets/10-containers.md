## What to build

Игрок поручает открыть контейнер, осмотреть содержимое, перенести предметы и закрыть окно; новый пилот выполняет этот существующий workflow и остаётся доступным для разговора.

Покрытие пользовательских историй спецификации: 8,10–13,16,18–19,28,36. Все решения о поведении принимает LLM; код обеспечивает контракты и исполнение. Это черновик для согласования разбиения; T-номера обозначают будущие задачи, а не опубликованные Issues.

## Acceptance criteria

- [ ] Перенесены open_window, inspect_window, transfer_item, close_window и связанный осмотр инвентаря.
- [ ] Оконными handle и очисткой продолжает владеть существующий общий оконный runtime; второй владелец не появляется.
- [ ] Соблюдается проверка оконной сессии, аргументов и актуального состояния до побочных эффектов; неверный JSON не превращается в допустимое закрытие окна.
- [ ] Отмена ответа модели не теряет факт уже выполненного переноса и не повторяет его при новой обработке.
- [ ] Проверены позднее открытие, отказ закрытия, timeout и прерывание выживанием; cleanup не задерживает независимые обязанности харнеса.
- [ ] Результаты и ошибки доставляются в тот же разговор, принятие не выдаётся за выполненный перенос.
- [ ] Приёмка проходит через публичный интерфейс с реальными правилами владения окном и управляемым внешним runtime.
- [ ] Для изменённого кода выполнены проверка типов, сборка и релевантные изолированные тесты; обычная проверка не запускает живого бота.
