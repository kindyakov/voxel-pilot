## What to build

Игрок может дописать сообщение во время генерации ответа. Пилот прерывает устаревающую обработку и учитывает все новые реплики, сохраняя уже принятое игровое действие и его результаты.

Покрытие пользовательских историй спецификации: 10,13–15,17,19,32. Все решения о поведении принимает LLM; код обеспечивает контракты и исполнение. Это черновик для согласования разбиения; T-номера обозначают будущие задачи, а не опубликованные Issues.

## Acceptance criteria

- [ ] Новый ввод сохраняется и учитывается актуальной обработкой; несколько последовательных реплик не заменяются одной последней.
- [ ] Поздний ответ отменённого запуска не начинает новых действий. Актуальность проверяется до принятия побочного эффекта.
- [ ] Отмена ответа не отменяет уже принятое харнесом действие и не приводит к его повторному запуску.
- [ ] История SDK остаётся допустимой после отмены до tool, между приёмом действия и результатом tool, после результата и во время следующего модельного обращения.
- [ ] Используется проверенный механизм SDK для остановки/продолжения; нет конкурентной повреждающей записи одной session и зависимости от непроверенного API ветки разработки.
- [ ] Повторная доставка сообщения с тем же идентификатором не создаёт повторную обработку поручения.
- [ ] Отмена конкретного ответа и остановка игровой цели доступны как разные явные операции.
- [ ] Гонки воспроизводятся детерминированно через публичный интерфейс; проверяются сообщения, история, принятые действия и отсутствие позднего вмешательства.
- [ ] Для изменённого кода выполнены проверка типов, сборка и релевантные изолированные тесты; обычная проверка не запускает живого бота.
