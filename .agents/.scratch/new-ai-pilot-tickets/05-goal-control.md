## What to build

Во время добычи игрок узнаёт прогресс или меняет поручение. LLM сама выбирает ответ, уточнение, продолжение, паузу либо замену; харнес корректно исполняет выбранную операцию. Недоступность модели не уничтожает цель.

Покрытие пользовательских историй спецификации: 8–13,16–17,21–22. Все решения о поведении принимает LLM; код обеспечивает контракты и исполнение. Это черновик для согласования разбиения; T-номера обозначают будущие задачи, а не опубликованные Issues.

## Acceptance criteria

- [ ] Вопрос о ходе работы получает актуальное состояние через инструменты/контекст; само сообщение и уточняющий вопрос модели не останавливают действие.
- [ ] Модели доступны типизированные операции управления целью; корректные пауза, продолжение, замена и завершение исполняются харнесом.
- [ ] Нет программной цепочки «неоднозначная поправка → вопрос → пауза», таймера автоматического решения за модель или классификатора фраз.
- [ ] При замене не возникает двух владельцев движения; новая цель не наследует результаты чужого поручения, а поздний исход старого не завершает новую.
- [ ] Транспортная недоступность, отклонение операции и отмена сохраняют предусмотренные разные исходы и бюджеты. Недоступность пилота не сбрасывает цель и не отключает автономное выживание.
- [ ] Игрок получает сообщения о существенных изменениях, препятствии и результате без обязательной реплики на каждый tool call.
- [ ] Изолированные сценарии проверяют выбранные моделью операции; отдельные прогоны реальной LLM оценивают выбор реакции на вопрос и поправку.
- [ ] Для изменённого кода выполнены проверка типов, сборка и релевантные изолированные тесты; обычная проверка не запускает живого бота.
