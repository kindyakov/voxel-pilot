## What to build

Игрок продолжает длинный разговор без отправки модели всего журнала на каждом ходе. Старые реплики сжимаются для модельного контекста, полный разговор и подтверждённые данные остаются доступны.

Покрытие пользовательских историй спецификации: 25–28,34. Все решения о поведении принимает LLM; код обеспечивает контракты и исполнение. Это черновик для согласования разбиения; T-номера обозначают будущие задачи, а не опубликованные Issues.

## Acceptance criteria

- [ ] Модель получает актуальные цель и исполнение, последние реплики, необходимые результаты и сводку старой истории в пределах выбранного контекстного бюджета.
- [ ] Сжатие не удаляет исходные сообщения и не меняет подтверждённые цель, прогресс или результаты.
- [ ] Сводка имеет границу охваченной истории; сообщения, поступившие во время её обновления, не теряются и не дублируются.
- [ ] Вход модели сохраняет корректные связи tool call/result; неполные фрагменты не превращаются в завершённые операции.
- [ ] Ошибка сжатия не разрешает превысить лимит контекста, потерять журнал или выдумать состояние исполнения.
- [ ] Механизм совместим с выбранным RouterAI-протоколом; OpenAI Responses-only compaction не предполагается доступным без проверки.
- [ ] Публичная приёмка подтверждает продолжение разговора после сжатия и после рестарта; отдельно оценено влияние сжатия на задержку и качество модели.
- [ ] Для изменённого кода выполнены проверка типов, сборка и релевантные изолированные тесты; обычная проверка не запускает живого бота.
