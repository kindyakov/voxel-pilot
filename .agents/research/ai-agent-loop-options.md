# Готовый серверный цикл пилота

Дата проверки: 2026-09-19. Статус: исследование; по его результатам выбран OpenAI Agents SDK, решение записано в [ADR-0006](../adr/0006-openai-agents-sdk-pilot.md). Зависимости не устанавливались, запросы к моделям и живому Minecraft-серверу не выполнялись.

## Исходная граница

Проект — Node.js >=24, TypeScript, XState; в `package.json` есть `openai`, но нет сравниваемых агентских SDK. `src/ai/client/factory.ts` поддерживает Responses и OpenAI-совместимые Chat Completions. По `ARCHITECTURE.md` и ADR-0003 исполнение, выживание и отмена принадлежат харнесу. ADR-0004 запрещает второго исполнителя и автоматический запуск сохранённых целей после рестарта. Смена SDK не отменяет эти контракты.

[assistant-ui runtime architecture](https://www.assistant-ui.com/docs/runtimes/concepts/architecture) описывает UI runtimes, протоколы и адаптеры к backend. Для обычного Minecraft-чата это полезная аналогия разделения слоёв; зависимость assistant-ui не требуется.

## Сравнение

| Кандидат | Готовая функциональность | Применимость здесь |
| --- | --- | --- |
| **Vercel AI SDK Core / ToolLoopAgent** | Цикл модель → инструменты → результаты, инструкции, история `messages`, streaming, `stopWhen`, `prepareStep`, отмена через `abortSignal`. | Подходит для готового модельного цикла с провайдерными адаптерами. Хранение диалога между запусками и правила входящих сообщений нужно интегрировать с приложением. |
| **OpenAI Agents SDK JS** | `Agent`/`Runner`, tools, streaming, ограничения ходов, `history` или `session` для продолжения разговора. | Полноценная альтернатива. OpenAI-совместимый endpoint поддерживается через provider `baseURL` и Chat Completions; Responses-only state/features нельзя переносить на него автоматически. |
| **LangChain createAgent / LangGraph** | Готовый агент, состояние разговора, middleware, checkpointer + `thread_id`, streaming сообщений/состояния/пользовательских событий. | Подходит при потребности в развитом графе агентского workflow. Для текущей задачи добавляет ещё один жизненный цикл состояния рядом с XState; это архитектурная цена, а не доказательство плохой производительности. |

Источники: [ToolLoopAgent](https://ai-sdk.dev/docs/reference/ai-sdk-core/tool-loop-agent), [AI SDK agents](https://ai-sdk.dev/docs/agents/overview), [loop control](https://ai-sdk.dev/docs/agents/loop-control), [OpenAI running agents](https://developers.openai.com/api/docs/guides/agents/running-agents), [OpenAI SDK providers](https://openai.github.io/openai-agents-js/guides/models/), [LangChain agents](https://docs.langchain.com/oss/javascript/langchain/agents), [LangChain streaming](https://docs.langchain.com/oss/javascript/langchain/streaming).

Все три допускают смену провайдера. У AI SDK есть отдельный [OpenAI Compatible Provider](https://ai-sdk.dev/providers/openai-compatible-providers); у LangChain — [ChatOpenAI с custom URL](https://docs.langchain.com/oss/javascript/integrations/chat/openai). Это поддержка протокола, не гарантия одинаковых tools, streaming, reasoning-настроек и ошибок каждого endpoint. Совместимость выбранной модели требует проверки. Текущая документация OpenAI SDK требует `openai` >=7.2 для переданного собственного клиента; имеющийся в проекте `^6.32.0` нельзя автоматически переиспользовать без проверки версии SDK.

## Что SDK не решает за проект

Следующее — проектные выводы, а не обещания библиотек:

- Ответ «сколько и какого дерева?» завершает текущий запуск модели, но не игровую цель. Следующее «10 дуба» должно продолжать тот же разговор. Завершение SDK-run, ожидание игрока и успех игровой цели — разные события.
- Неоднозначность определяет модель по инструкциям и истории. Код проверяет форму аргументов и допустимость исполнения, а не распознаёт фразу «добудь дерево». Поиск ресурсов нужен для достоверного уточнения; поиск не должен запускать добычу.
- Долгий tool, который `await`-ит всю добычу, удерживает текущий run. Сам SDK не определяет, как ответить на новое «ты где?» во время него. Нужно выбрать контракт: ожидание результата с отдельной обработкой сообщений либо запуск действия с идентификатором и последующее событие результата. Во втором случае «принято харнесом» нельзя выдавать за «выполнено»; постоянный LLM-polling не нужен.
- Прерывание модели должно доходить до исполнителя, а поздние ответы старого запуска не должны менять новую цель. `AbortSignal` сетевого запроса сам по себе не останавливает Mineflayer. Единственный владелец движения остаётся HSM.
- В чат следует передавать смысловые сообщения и подтверждённые стадии исполнения, не поток скрытых рассуждений и не каждый токен отдельной репликой.

## Выбор и проверка скорости

При заявленном приоритете готовой расширяемой агентской инфраструктуры выбран **OpenAI Agents SDK**. У SDK есть готовый контракт sessions для истории между запусками и runner с handoffs; это снижает объём собственной агентской инфраструктуры при соответствующем развитии продукта. Наличие XState само по себе не даёт преимущества одному из двух SDK: оба могут работать поверх харнеса. Конкретный набор будущих расширений ещё не согласован; принят выбор библиотеки, но не детальная схема интеграции.

Источники: [Agents SDK и границы его ответственности](https://developers.openai.com/api/docs/guides/agents), [sessions и пользовательское хранилище](https://openai.github.io/openai-agents-js/guides/sessions/). Через RouterAI предполагается OpenAI-совместимый Chat Completions; поддержку конкретных моделей, streaming tools и отмены нужно проверить отдельно. Готовый Session-интерфейс не означает готовое постоянное хранилище или автоматическую переносимость Responses-only возможностей. LangGraph остаётся кандидатом при требованиях к сложным сохраняемым агентским workflows.

Ни один SDK не обещает запуск действия за 2 секунды. Для понятного поручения измерять отдельно время до первого текста, готового tool call, принятия действия HSM и фактического движения; считать p50/p95 и число обращений к модели. Для «поиск → уточнение» учитывать как минимум дополнительный запрос после результата поиска. Отключение reasoning проверять только поддерживаемой настройкой конкретной модели и провайдера, вместе с качеством уточнений и корректностью tools. Ускорение первого текста не равно ускорению старта действия.

Примечание о проверке источников: страницы AI SDK, которые web-инструмент не смог открыть из-за `text/markdown`, прочитаны с официального сайта через `.md`; примеры API из разных major-версий смешивать нельзя. Перед реализацией требуется зафиксировать выбранные версии и проверить их типы.
