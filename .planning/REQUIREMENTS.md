# Требования: VoxelPilot

**Определены:** 2026-04-14
**Майлстоун:** MVP Solo Companion Runtime
**Ключевая ценность:** бот обязан оставаться функционально полезным и структурно целым, даже когда LLM галлюцинирует, таймаутится или возвращает плохие решения, и даже когда AI полностью недоступен.

## Требования v1

### Целостность рантайма

- [ ] **RT-01**: пользователь может дать боту гол, и HSM остаётся в валидном состоянии, даже когда LLM возвращает malformed-, irrelevant- или missing-вывод инструментов.
- [ ] **RT-02**: пользователь может прервать, остановить или заменить активный гол без осиротевшего состояния задач и падения процесса бота.
- [ ] **RT-03**: пути старта, реконнекта и сбоев рантайма оставляют бота восстанавливаемым, а не молча повреждённым.
- [ ] **RT-04**: без AI (режим без LLM) бот сохраняет автономное выживание — мониторинг, тактический отход, еда из инвентаря, самооборона с оружием, декоративный взгляд — без добычи ресурсов и без падения HSM.
- [ ] **RT-05**: при транспортном сбое AI или таймауте активный гол игрока ставится на паузу (не сбрасывается) с возможностью resume в `THINKING` при появлении AI.
- [ ] **RT-06**: старт-тоггл AI: при `AI_PROVIDER=disabled` бот стартует и работает в режиме без AI; команды `:stop` и другие работают; при подключении AI бот переходит в режим с пилотом.

### Инструменты агента

- [ ] **TL-01**: агент использует MVP-набор ограниченных инструментов только через OpenAI-совместимые tool calls; произвольное исполнение свободных действий запрещено.
- [ ] **TL-02**: невалидные или галлюцинированные вызовы инструментов отвергаются, логируются и возвращаются в цикл агента как структурные сбои, а не роняют исполнение.
- [ ] **TL-03**: рантайм поддерживает и атомарные инструменты, и ограниченные высокоуровневые инструменты/стейты задач, чтобы агент решал проблемы без пошагового микроменеджмента.

### Постоянная память

- [ ] **MEM-01**: бот хранит долгоживущую память между рестартами в SQLite и восстанавливает релевантный контекст задач в следующей сессии.
- [ ] **MEM-02**: агент может читать и обновлять память локаций, контейнеров, ресурсов, меток опасности и истории голов/задач прямо во время исполнения.

### Геймплейные способности

- [ ] **GP-01**: пользователь может попросить бота добыть базовые ресурсы выживания end-to-end в живой игре.
- [ ] **GP-02**: во время задачи бот обрабатывает типовые прерывания выживания — риск низкой еды, полный инвентарь, отсутствующие/сломанные инструменты — без коллапса HSM.
- [ ] **GP-03**: бот может защищать себя и помогать игроку в бою без необратимого разрыва непрерывности задач.

### Верификация

- [ ] **VR-01**: MVP-подсистемы принимаются только после прохождения и точечных автотестов, и внутриигровых сценариев проверки.

## Требования v2

### Будущие семейства способностей

- **FC-01**: пользователь может делегировать фермерские циклы через выделенное ограниченное семейство задач/стейтов `FARMING`.
- **FC-02**: пользователь может делегировать структурные строительные работы через выделенное ограниченное семейство задач/стейтов `BUILDING`.

## Вне скоупа

| Фича                                                        | Причина                                                                      |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Координация нескольких ботов                                | Слишком сложно для закалки MVP-рантайма                                      |
| Веб-UI реального времени / инспектор HSM                    | Наблюдаемость пригодится позже, но не разблокирует пользу MVP в геймплее     |
| Широкие новые макро-семейства стейтов сверх MVP-набора      | Сначала стабилизировать контракт рантайма, потом растить поведенческую поверхность |
| Поддержка не-OpenAI-совместимых AI-провайдеров в MVP        | Снизить вариативность интеграций, пока закаляется контракт агента/инструментов |
