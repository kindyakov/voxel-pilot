# Сопровождение патчей зависимостей

Эти патчи исправляют отмену внутри плагинов для [задачи #9](https://github.com/kindyakov/voxel-pilot/issues/9). HSM выбирает владельца поведения, но отменённый плагин также обязан прекратить собственные отложенные действия. Исправления находятся у владельцев операций, а не в runtime-подменах методов.

- `mineflayer-pvp`: поколение атаки, отмена ожидания остановки пути и таймеров щита; очистка только собственных подписок и использования предмета.
- `mineflayer-auto-eat`: `eatingTimeout` ограничивает всю попытку — экипировку, употребление и восстановление предмета. Отмена/тайм-аут освобождают попытку сразу, даже при зависшем вызове; старое завершение не очищает новую попытку. `strictErrors` в адаптере передаёт отказ recovery-актору.
- `mineflayer`: отменяемая экипировка использует slot SWAP без предмета на курсоре; отмена между шагами может оставить частичную перестановку, но все предметы остаются в слотах. Для offhand/брони промежуточный слот неактивен; отменяемая ветка принимает источник из inventory/hotbar/offhand. Окно и курсор проверяются перед отправкой отложенного SWAP. Generic `moveSlotItem` не предоставляет отмену посреди cursor transaction. `AbortSignal` также проходит через установку блока: проверка после ожидания поворота выполняется до отправки `block_place`. Уже отправленный серверу пакет отменить нельзя.
- `mineflayer-pathfinder`: продолжения копания, установки блоков и открытия проходов проверяют поколение маршрута; установка получает собственный `AbortSignal`. После синхронных `path_update`/`goal_reached` также проверяется поколение: обработчик события может отменить путь или установить новый. Остановка сохраняет чужие подписки.
- `minecrafthawkeye`: смена цели с тем же оружием сохраняет натяжение. Остановка очищает цель, отменяет ожидающую экипировку и отменяет собственное натяжение сменой выбранного слота, без `RELEASE_USE_ITEM` и раннего выстрела; синхронная передача владения не должна восстановить старый слот поверх нового. Уже попавший в очередь physics callback не возобновляет использование предмета. Upstream: [HawkEye #26](https://github.com/sefirosweb/minecraftHawkEye/issues/26).

## Установка и обновление

`patches/` должен присутствовать рядом с `package.json` до установки. Выполняй обычный `npm ci` с lifecycle scripts: `postinstall` применяет патчи и завершает установку ошибкой, если применить их нельзя. При установке с `--ignore-scripts` отдельно выполни `rtk npm run postinstall` до тестов, сборки или запуска. `patch-package` намеренно находится в runtime dependencies, чтобы работать и при `--omit=dev`.

Версии исправленных пакетов закреплены точно. При обновлении любого из них:

1. Проверь исправления upstream и повтори тесты отмены на новой версии. Удаляй патч только после подтверждения его контракта тестами без патча.
2. Если исправление всё ещё нужно, перенеси его в новую версию зависимости и пересоздай файл через `rtk npx patch-package <package>`. Изменения только в `node_modules` не являются завершённым результатом.
3. Проверь применение патчей на исходных файлах пакетов, затем выполни `rtk npx tsx --test src/tests/hsm/controlHandoff.runtime.test.ts`, все тесты проекта, type-check и build. Сохраняй обновлённые версии, lockfile и патчи вместе.

Основной интеграционный seam — `src/tests/hsm/controlHandoff.runtime.test.ts`: настоящие HSM, акторы и плагины; подменена граница Minecraft, перемещение считается настоящей физикой. Проверки отмены должны сопровождаться успешным новым запуском, чтобы полная поломка плагина не выглядела исправлением.

Native-контракты отдельно покрыты `nativeEquip.runtime.test.ts`, `eatingDeadline.runtime.test.ts` и `rangedInventory.runtime.test.ts`: сохранность предметов после отмены, новая попытка еды, полное натяжение при retarget и отсутствие release-пакета при отмене. Серверный плагин может запретить смену слота; это требует живой проверки в конкретном окружении.

## Ручная проверка на сервере

С едой в инвентаре войди в бой и снизь здоровье ниже текущего порога восстановления. Бот должен прекратить атаку и несколько секунд увеличивать расстояние до врага; поднятый щит или завершившаяся старая экипировка не должны останавливать побег. Повтори с прерыванием еды, смертью/респавном и остановкой бота. Серверная задержка и геометрия мира требуют отдельной живой проверки; локальная физическая симуляция их не заменяет.

Патчи не меняют приоритеты HSM, пороги, выбор ближайшего врага или поведение без еды: это отдельные задачи спецификации.
